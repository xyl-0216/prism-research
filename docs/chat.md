# 交互式 CLI 与多轮会话

在终端启动一次 `prism-research chat`，即可连续聊天、附加资料、开展研究并追问结果。回答按生成进度显示，研究过程显示调用阶段和网页来源。此模式是研究助手，不提供执行任意系统命令或修改代码的工具。

## Windows 启动

已有项目环境可以直接运行，无需重新安装：

```powershell
Set-Location D:\agent\prism-research
.\.venv\Scripts\prism-research.exe chat --env-file "..\open_deep_research\.env"
```

出现 `prism ›` 后输入普通中文消息即可。普通对话通常只调用一次模型，不会自动启动完整研究或联网检索。

启动命令各部分的含义：

| 部分 | 含义 |
|---|---|
| `.\.venv\Scripts\prism-research.exe` | 从当前项目的 Python 虚拟环境启动已安装的 CLI |
| `chat` | 进入持续输入的多轮会话模式 |
| `--env-file "..\open_deep_research\.env"` | 相对当前工作目录读取 API 配置；该示例指向相邻项目目录，也可换成自己的 `.env` |
| `--pdf-backend api-rerank` | 之后研究 PDF 时使用 API 页面重排；该参数本身不会打开 PDF 或部署本地模型 |

未传 `--model` 时默认使用 `openai:qwen3.5-flash`，可在会话中输入 `/status` 查看；不要仅凭模型自己回答的名称判断实际配置。空行不调用模型。在输入提示符处按 Ctrl+C 只取消当前输入，`/exit` 保存退出。

例如：

```text
prism › 我想学习 Agent，先解释一下规划、工具调用和记忆的区别。
prism › 刚才第二个部分能举一个例子吗？
prism › 用更简单的语言重新解释。
```

## 附加资料、研究和追问

```text
prism › /attach "D:\资料\论文.pdf"
prism › /research 总结这篇论文的主要方法、实验条件和局限。
prism › 刚才提到的检索模块为什么需要重排？
prism › /research 继续核对论文中重排模块的实验结果。
prism › /report
prism › /steps
```

PDF 使用 API 重排时，启动命令加 `--pdf-backend api-rerank`。也可通过启动参数 `--image` 或 `--pdf` 直接附加资料。

`/attach` 支持 PNG、JPEG、PDF，每种类型保留一个当前附件。重复附加同一类型会替换当前选择，不删除历史文件。文件复制到会话目录并保存哈希，恢复时不依赖原路径；文件被改动后会要求重新附加。图片仍遵循原有 6 MB 与像素限制，所有附件最多 50 MB，PDF 研究另受所选后端的页数限制。

**附加文件并不代表模型已经阅读它。** 用 `/research` 执行证据研究后，普通追问会携带最近报告的结论与有界原文片段。需要读取更多原文、重新核验或补充新证据时，再执行 `/research`。聊天回答没有结构化研究报告的严格引用校验，不应作为新的实测结果。

联网研究：

```text
prism › /web on
prism › /research 查询 LangGraph 官方文档，解释 checkpoint 和长期记忆的区别。
```

联网仍受项目当前来源白名单限制，无法搜索所有网站。默认不用商品研究模式；需要时可在新会话启动参数中显式加 `--shopping`。`/web off` 会同时关闭本会话的商品模式。

## 保存和恢复

每轮开始前及结束后自动保存，输入 `/exit` 或终端 EOF 退出。程序会打印会话 ID。

```powershell
# 查看会话，不调用模型
.\.venv\Scripts\prism-research.exe chat --list

# 替换下面的会话 ID
.\.venv\Scripts\prism-research.exe chat --resume 20261028-203206-6d61607b --env-file "..\open_deep_research\.env"
```

会话默认位于项目 `.prism/sessions/`，已被 Git 忽略。实际 ID 以 `/status` 或 `--list` 输出为准。`--session-dir` 可指定其他存储根目录；恢复时需使用相同根目录。模型、研究参数、长期记忆命名空间和预算沿用保存的会话设置；恢复命令中的同名初始配置不会覆盖它们。密钥从环境或 `--env-file` 重新读取，不写入会话设置。

每个会话包含：

- `session.json`：完整已完成对话、失败/中断状态、当前附件、压缩缓存与报告路径。
- `assets/`：用户明确附加的资料副本。
- `turns/`：每轮独立预算和日志；研究轮还包含 HTML/Markdown/JSON 报告及证据。

恢复会话会继续对话背景；它不会接着执行崩溃或中断时的半条研究图。中断轮保留记录，下一轮重新提出问题。同一会话不允许两个终端同时打开。

## 命令

| 命令 | 用途 |
|---|---|
| 普通输入 | 聊天和已有结果追问，不自动联网 |
| `/research 问题` | 携带当前会话背景启动一轮完整研究 |
| `/attach 路径` | 添加/替换当前图片或 PDF，含空格路径可加引号 |
| `/detach image`、`/detach pdf` | 移除当前附件选择 |
| `/web on`、`/web off` | 开启/关闭后续研究的联网能力 |
| `/report` | 查看最近成功写出的研究报告路径 |
| `/steps` | 查看最近一轮调用阶段和日志路径 |
| `/history` | 查看完整会话记录 |
| `/status` | 查看当前设置、附件和已用请求数 |
| `/paste` | 多行输入，单独一行 `.` 结束 |
| `/help` | 查看命令帮助 |
| `/exit` | 保存退出 |

研究中按 Ctrl+C 取消本轮，回到输入提示符。已经发送的请求仍可能由服务端计费，客户端取消不能撤销它们。流式回答中途失败时可能已经显示部分文字，该部分不会作为完整回答加入后续上下文。

## 上下文与费用

普通对话把完整历史按用户/助手角色送入现有上下文压缩模块，达到阈值时压缩较早内容，保留近期消息和首轮问题。摘要缓存随会话保存，恢复后不会重复压缩相同前缀。完整历史仍保留在本地。最近报告的原文片段受长度限制；摘要或旧报告不能当作新的实时证据。

新的 `/research` 传入最近六个已完成回合的有界背景及已有会话摘要，并重新登记当前资料。历史来源 URL 仍需经过站点检查和重新读取，不能把旧价格当当前价格。这个阶段传入的背景不保证包含所有旧细节，重要条件建议在研究问题中重申。

默认 Flash 模型。普通聊天每轮最多 2 次请求（可能包含一次上下文压缩），完整研究默认最多 16 次请求。会话默认累计最多 100 次，通过新会话的 `--session-max-requests` 设置；`--max-requests` 设置每轮上限。失败、中断和恢复均保留已经预留的请求计数。这些是请求次数限制，不是人民币费用保证。

跨会话长期记忆与当前会话记录相互独立。新会话默认使用独立记忆命名空间，也可显式指定 `--memory-namespace`。`--no-memory` 关闭长期记忆读写，但不关闭当前会话保存和上下文。

## 验证

```powershell
.\.venv\Scripts\python.exe -m pytest -q

# 付费小样本：三轮聊天，含一次退出恢复，最多六次请求
.\.venv\Scripts\python.exe scripts/chat_smoke.py --env-file "..\open_deep_research\.env" --output runs/chat-check-new
```

离线测试覆盖多轮角色历史、研究背景传递、报告证据复用、附件副本、会话锁、中断记账和压缩缓存恢复。真实小样本验证了普通聊天的流式输出、跨轮条件记忆和恢复后的延续；不代表所有长对话和复杂研究任务的正确率。
